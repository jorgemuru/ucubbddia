Data Warehouse

Un Data Warehouse es una base de datos analítica pensada para integrar datos históricos de distintas fuentes, organizarlos con criterios de negocio y facilitar consultas, tableros, reportes, ciencia de datos e inteligencia artificial.

Integra

Une datos de ventas, clientes, pagos, logística, web, sensores, archivos y sistemas externos.

Historiza

Conserva la evolución del negocio para comparar períodos, tendencias y comportamientos.

Prepara para IA

Organiza datasets confiables para predicción, segmentación, recomendación y automatización.

Definición práctica

¿Qué problema resuelve?

Sin Data Warehouse

Los datos están dispersos. Cada área usa planillas, sistemas o bases diferentes. Las respuestas no coinciden y el análisis consume tiempo limpiando datos.

Con Data Warehouse

Los datos se integran, limpian, documentan y estructuran. El analista consulta una fuente común y puede construir indicadores, datasets y modelos.

Movimiento de datos

ETL y ELT

ETL

Extract, Transform, Load. Primero se extraen los datos, luego se transforman y finalmente se cargan al warehouse. Es útil cuando se quiere controlar la limpieza antes de cargar.

ELT

Extract, Load, Transform. Primero se cargan los datos y luego se transforman dentro del motor analítico. Es frecuente en soluciones modernas en la nube y grandes volúmenes.

-- Ejemplo simple de transformación para análisis CREATE VIEW vw_ventas_mensuales AS SELECT DATE_TRUNC('month', fecha_venta) AS mes, id_producto, SUM(cantidad) AS unidades, SUM(importe) AS facturacion FROM ventas GROUP BY DATE_TRUNC('month', fecha_venta), id_producto;
Diseño para análisis

Modelo dimensional

El modelo dimensional organiza los datos para responder preguntas de negocio de forma rápida y comprensible. La decisión más importante es definir el grano: qué representa exactamente cada fila de la tabla de hechos.

Grano

Nivel de detalle de cada fila: una venta, una línea de venta, una visita web, un pago.

Hechos

Eventos medibles: ventas, reservas, pagos, clics, reclamos. Incluyen claves a dimensiones.

Dimensiones

Contexto del hecho: cliente, producto, fecha, sucursal, canal, promoción.

Métricas

Valores agregables: cantidad, importe, costo, descuento, duración, conteos.

Ejemplo

fact_ventas: id_fecha, id_cliente, id_producto, id_sucursal, cantidad, importe_total.

dim_cliente: segmento, edad, barrio. dim_producto: categoría, marca, precio_lista.

Relación con IA

Desde estas tablas se generan variables como gasto promedio, frecuencia de compra, productos favoritos, estacionalidad y probabilidad de recompra.

Buenas prácticas

Calidad de datos para IA

Un modelo de IA no mejora mágicamente datos malos. El Data Warehouse debe asegurar que las consultas generen información confiable, reproducible y auditada.

Completitud

Evitar valores faltantes críticos o documentar cómo se imputan.

NULL controlado

Consistencia

Unificar formatos, monedas, unidades, códigos y nombres de categorías.

Catálogos

Trazabilidad

Saber origen, fecha de carga, reglas aplicadas y versión del dato.

Linaje

Privacidad

Controlar accesos, anonimizar identificadores y proteger datos sensibles.

Gobierno

Reglas típicas

  • Validar claves foráneas y duplicados.
  • Rechazar importes negativos cuando no correspondan.
  • Normalizar fechas, zonas horarias y monedas.
  • Registrar errores de carga para revisión.

Impacto en IA

Mejores datos reducen sesgos accidentales, errores de entrenamiento y conclusiones contradictorias entre reportes, dashboards y modelos.

SQL aplicado

Consultas típicas para analistas

-- Ticket promedio y cantidad de compras por cliente SELECT c.id_cliente, c.segmento, COUNT(v.id_venta) AS compras, SUM(v.importe) AS gasto_total, AVG(v.importe) AS ticket_promedio, MAX(v.fecha_venta) AS ultima_compra FROM fact_ventas v JOIN dim_cliente c ON c.id_cliente = v.id_cliente GROUP BY c.id_cliente, c.segmento HAVING COUNT(v.id_venta) >= 3 ORDER BY gasto_total DESC;

Este tipo de consulta puede alimentar un dashboard o generar variables para un modelo de predicción de abandono, recomendación o segmentación.

Mapa de estudio

Qué recordar

Conceptos

Data Warehouse, OLTP, OLAP, ETL, ELT, Staging, Data Mart, Data Lake, Lakehouse, tabla de hechos y dimensiones.

Habilidades SQL

JOIN, GROUP BY, HAVING, agregaciones, vistas, limpieza de datos, filtros, variables analíticas y consultas reproducibles.

Criterio analítico

Antes de consultar, definir pregunta, granularidad, período, fuente, métrica y regla de negocio.

Errores comunes

  • Confundir base transaccional con base analítica.
  • No definir el grano de la tabla de hechos.
  • Usar datos sin validar calidad, origen o fecha de carga.
  • Entrenar IA con variables que producen fuga de información.

Ruta sugerida

  1. Entender el negocio.
  2. Identificar fuentes.
  3. Modelar hechos y dimensiones.
  4. Consultar con SQL.
  5. Construir indicadores y variables para IA.

Idea final: un Data Warehouse transforma datos operativos en conocimiento analítico; ese conocimiento puede convertirse en decisiones, tableros o modelos de IA.
