¿Qué es SQL?

SQL

SQL significa Structured Query Language. Es el lenguaje usado para trabajar con bases de datos relacionales.

Permite crear estructuras, insertar datos, consultar información, actualizar registros y eliminar datos.

Dos grandes grupos

Para este ejercicio nos interesan especialmente:

  • DDL: define la estructura de la base de datos.
  • DML: manipula los datos almacenados.

DDL: Data Definition Language

¿Para qué sirve DDL?

DDL se usa para definir, modificar o eliminar estructuras dentro de una base de datos.

En este ejercicio, DDL se utiliza para crear la base de datos y las tablas: clientes, productos y ventas.

Comandos frecuentes

Comando Uso
CREATECrear bases, tablas u otros objetos.
ALTERModificar una estructura existente.
DROPEliminar una estructura.
TRUNCATEVaciar una tabla rápidamente.

DML: Data Manipulation Language

¿Para qué sirve DML?

DML se usa para trabajar con los datos que están guardados en las tablas.

En este ejercicio, DML se usa para insertar los registros de clientes, productos y ventas.

Comandos frecuentes

Comando Uso
INSERTAgregar nuevos registros.
SELECTConsultar datos.
UPDATEModificar datos existentes.
DELETEEliminar registros.

Modelo del ejercicio

Antes de escribir SQL, conviene identificar entidades, atributos, claves primarias y relaciones.

clientes

Clave primaria: cédula.

  • cedula
  • nombre
  • apellido
  • direccion
  • telefono
  • email

productos

Clave primaria: código.

  • codigo
  • descripcion
  • precio
  • stock

ventas

Relaciones:

  • cliente → clientes.cedula
  • producto → productos.codigo

Cada venta registra qué cliente compró qué producto.

Es recomendable agregar un identificador propio para cada venta, por ejemplo id_venta.

Guía para crear las tablas

1Crear la base de datos

Usa CREATE DATABASE para crear el espacio donde estarán las tablas.

CREATE DATABASE nombre_base;
2Seleccionarla

Usa USE para indicar que trabajarás sobre esa base.

USE nombre_base;
3Crear tablas principales

Primero crea las tablas que no dependen de otras.

CREATE TABLE clientes (...);
CREATE TABLE productos (...);
4Crear tabla relacionada

Luego crea la tabla que referencia a las anteriores.

CREATE TABLE ventas (
    ...,
    FOREIGN KEY (...) REFERENCES ...(...)
);
Orden importante: primero clientes y productos, luego ventas.

Sintaxis DML utilizada

Para cargar datos se utiliza principalmente la sentencia INSERT INTO.

Insertar un registro
INSERT INTO nombre_tabla (campo1, campo2, campo3)
VALUES (valor1, valor2, valor3);
Insertar varios registros
INSERT INTO nombre_tabla (campo1, campo2, campo3) VALUES
(valor1, valor2, valor3),
(valor1, valor2, valor3),
(valor1, valor2, valor3);
Consultar datos insertados
SELECT * FROM nombre_tabla;
Para cargar ventas, los clientes y productos usados en cada venta deben existir previamente.

Guía para resolver el ejercicio

Las tablas son clientes, productos y ventas. Cada tabla representa un conjunto de datos del sistema.

Una clave primaria identifica de forma única cada registro. Para este ejercicio: clientes.cedula y productos.codigo pueden ser claves primarias. En ventas conviene agregar id_venta.

Textos como nombres, direcciones y correos pueden ser VARCHAR. Precios e importes pueden ser DECIMAL(10,2). Cantidades y stock pueden ser INT. Fechas pueden ser DATE.

La tabla ventas debe guardar el cliente y el producto de cada compra. Por eso se usan claves foráneas hacia clientes y productos.

Primero inserta los clientes, luego los productos y finalmente las ventas. Así se evitan errores de claves foráneas.

Verificación del trabajo

Luego de ejecutar los scripts, se puede verificar si las tablas tienen datos.

Consultar todos los clientes
SELECT * FROM clientes;
Consultar todos los productos
SELECT * FROM productos;
Consultar todas las ventas
SELECT * FROM ventas;
Contar registros
SELECT COUNT(*) FROM nombre_tabla;
Si cada tabla devuelve 20 registros, la carga básica fue realizada correctamente.

CREATE DATABASE IF NOT EXISTS gestion_ventas;

USE gestion_ventas;

CREATE TABLE clientes (
    cedula VARCHAR(20) PRIMARY KEY,
    nombre VARCHAR(50) NOT NULL,
    apellido VARCHAR(50) NOT NULL,
    direccion VARCHAR(100),
    telefono VARCHAR(20),
    email VARCHAR(100) UNIQUE
);

CREATE TABLE productos (
    codigo INT PRIMARY KEY,
    descripcion VARCHAR(100) NOT NULL,
    precio DECIMAL(10,2) NOT NULL CHECK (precio >= 0),
    stock INT NOT NULL CHECK (stock >= 0)
);

CREATE TABLE ventas (
    id_venta INT AUTO_INCREMENT PRIMARY KEY,
    fecha DATE NOT NULL,
    cliente VARCHAR(20) NOT NULL,
    producto INT NOT NULL,
    cantidad INT NOT NULL CHECK (cantidad > 0),
    importe DECIMAL(10,2) NOT NULL CHECK (importe >= 0),

    CONSTRAINT fk_ventas_clientes
        FOREIGN KEY (cliente)
        REFERENCES clientes(cedula),

    CONSTRAINT fk_ventas_productos
        FOREIGN KEY (producto)
        REFERENCES productos(codigo)
);
USE gestion_ventas;
