Integridad de datos
Reglas de integridad

PK, FK y reglas que protegen los datos

PK · Primary Key

Identifica de forma única cada fila de una tabla. No debe repetirse y no debería ser nula.

cliente.id_cliente

FK · Foreign Key

Permite relacionar una tabla con otra, asegurando que el valor exista en la tabla referenciada.

venta.id_cliente

Constraints

Reglas como NOT NULL, UNIQUE, CHECK y DEFAULT reducen errores en los datos.

Tablas, relaciones y normalización
Diseño lógico

Normalización: evitar redundancia y anomalías

¿Para qué sirve?

La normalización organiza los datos en tablas relacionadas para evitar duplicación innecesaria, inconsistencias y problemas al insertar, actualizar o borrar registros.

Idea didáctica: cada dato debe vivir en el lugar correcto.

FormaObjetivo inicialEjemplo simple
1FNValores atómicos, sin listas en una celda.No guardar “café, té, agua” en una sola columna.
2FNEvitar dependencias parciales en claves compuestas.Separar datos del producto del detalle de venta.
3FNEvitar dependencias transitivas.No repetir datos de localidad dentro de cada cliente si hay tabla Localidad.
ACID · Transacciones
Confiabilidad

ACID y transacciones

Una transacción es un conjunto de operaciones que debe ejecutarse como una unidad lógica. En una venta, por ejemplo, registrar la venta y actualizar el stock deberían confirmarse juntos.

A

Atomicidad: todo se realiza o nada se realiza.

C

Consistencia: los datos pasan de un estado válido a otro válido.

I

Aislamiento: transacciones simultáneas no deberían interferir incorrectamente.

D

Durabilidad: al confirmar, los cambios persisten.

START TRANSACTION; INSERT INTO venta(id_cliente, fecha, importe) VALUES (1, CURRENT_DATE, 180); UPDATE producto SET stock = stock - 1 WHERE id_producto = 10; COMMIT; -- o ROLLBACK si ocurre un error
DBMS · MySQL
Motor de base de datos

DBMS: el caso de MySQL

¿Qué hace un DBMS?

  • Almacena y administra datos.
  • Controla usuarios, permisos y seguridad.
  • Ejecuta consultas SQL.
  • Mantiene integridad y transacciones.
  • Gestiona índices, respaldos y concurrencia.

MySQL

Es un DBMS relacional ampliamente usado en aplicaciones web, sistemas académicos, comercio electrónico y análisis inicial de datos.

Para el curso, permite practicar diseño físico, creación de tablas, claves, restricciones y consultas CRUD.

CRUD

DDL

Define estructura: bases, tablas, restricciones, vistas e índices.

CREATE TABLE cliente ( id_cliente INT PRIMARY KEY, nombre VARCHAR(80) NOT NULL );

SQL para datasets
Consulta analítica

De tablas relacionales a un dataset para IA

El valor analítico aparece cuando combinamos tablas con JOIN, filtramos, agrupamos y calculamos variables.

-- Total comprado por cliente: posible variable para segmentación o recomendación SELECT c.id_cliente, c.nombre, c.preferencia, COUNT(v.id_venta) AS cantidad_compras, SUM(v.importe) AS total_gastado FROM cliente c LEFT JOIN venta v ON v.id_cliente = c.id_cliente GROUP BY c.id_cliente, c.nombre, c.preferencia;
Resultado esperado: una tabla preparada para análisis, donde cada fila representa un cliente y las columnas resumen su comportamiento.
Caso real
Ejemplo de la vida real

Cantina universitaria + IA

Contexto

La cantina desea registrar clientes, preferencias de alimentos y bebidas, ventas, fecha/hora, producto, cantidad, importe total y medio de pago.

Objetivo analítico: predecir demanda diaria y recomendar productos según historial y preferencias.

Posible modelo inicial

ClienteProductoVentaDetalleVentaPreferenciaMedioPago

La relación Cliente–Venta permite analizar comportamiento. Producto–DetalleVenta permite calcular demanda, ticket promedio y patrones de consumo.

-- Productos más vendidos por franja horaria SELECT p.nombre, HOUR(v.fecha_hora) AS hora, SUM(dv.cantidad) AS unidades FROM venta v JOIN detalle_venta dv ON dv.id_venta = v.id_venta JOIN producto p ON p.id_producto = dv.id_producto GROUP BY p.nombre, HOUR(v.fecha_hora);
