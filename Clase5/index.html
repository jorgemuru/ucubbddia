Consultas: transformar datos en preguntas respondidas

Una consulta SQL permite recuperar, filtrar, unir, agrupar y ordenar datos. Para un analista, SQL es la herramienta que convierte tablas en indicadores, datasets y evidencia.

IA Una buena consulta puede generar las variables de entrada para un modelo predictivo.

-- Ventas por producto y día SELECT p.nombre, DATE(v.fecha_hora) AS fecha, SUM(dv.cantidad) AS unidades, SUM(dv.cantidad * dv.precio_unitario) AS total FROM venta v JOIN detalle_venta dv ON dv.id_venta = v.id JOIN producto p ON p.id = dv.id_producto WHERE v.fecha_hora >= '2026-01-01' GROUP BY p.nombre, DATE(v.fecha_hora) ORDER BY fecha, total DESC;

Índices
Concepto

Índices: el índice del libro aplicado a una tabla

Analogía

Buscar un tema en un libro sin índice obliga a revisar página por página. En una tabla grande ocurre algo parecido: sin índice, el DBMS puede recorrer muchos registros para encontrar pocos resultados.

Función

Un índice crea una estructura auxiliar que ayuda a localizar datos más rápido, especialmente en columnas usadas en WHERE, JOIN, ORDER BY o GROUP BY.

-- Índice para acelerar búsquedas por cliente y fecha CREATE INDEX idx_venta_cliente_fecha ON venta (id_cliente, fecha_hora);

Regla práctica: indexar columnas muy consultadas, no todas las columnas.

Índices
Beneficio vs costo

Los índices aceleran lecturas, pero no son gratis

Mejoran

Consultas selectivas, búsquedas por clave, joins y ordenamientos frecuentes.

Consumen

Espacio adicional en disco/memoria porque el índice es una estructura extra.

Penalizan

INSERT, UPDATE y DELETE, porque el DBMS debe actualizar también los índices.

Optimización
Buenas prácticas

Optimización de consultas y scripts SQL

Antes

-- Trae columnas innecesarias y filtra tarde SELECT * FROM venta v, cliente c WHERE v.id_cliente = c.id AND YEAR(v.fecha_hora) = 2026;

Después

-- Columnas necesarias y filtro compatible con índice SELECT c.id, c.nombre, COUNT(*) AS compras FROM venta v JOIN cliente c ON c.id = v.id_cliente WHERE v.fecha_hora >= '2026-01-01' AND v.fecha_hora < '2027-01-01' GROUP BY c.id, c.nombre;
Optimización
Medir antes de cambiar

EXPLAIN: leer cómo piensa el DBMS

EXPLAIN muestra el plan de ejecución: qué tablas se leen, qué índices se usan, qué orden de joins se aplica y cuántas filas se estiman procesar.

Es clave para decidir si una consulta necesita índice, reescritura o cambios de diseño.

-- En MySQL EXPLAIN SELECT c.nombre, SUM(dv.cantidad) AS unidades FROM cliente c JOIN venta v ON v.id_cliente = c.id JOIN detalle_venta dv ON dv.id_venta = v.id WHERE c.id = 15 GROUP BY c.nombre;
Señales de alerta: muchas filas estimadas, escaneo completo de tabla cuando se esperaba índice, filtros aplicados tarde o joins innecesarios.
Scripts
Scripts más seguros y mantenibles

Optimización de scripts SQL

Buenas prácticas

  • Usar transacciones para operaciones críticas.
  • Evitar cambios masivos sin WHERE.
  • Separar DDL, DML y datos de prueba.
  • Nombrar PK, FK, índices y constraints.
  • Probar primero con una copia o ambiente de desarrollo.

Para analítica e IA

  • Crear vistas para datasets reutilizables.
  • Documentar variables generadas.
  • Evitar duplicaciones involuntarias.
  • Validar nulos y outliers antes de entrenar modelos.
  • Automatizar cargas de datos con control de errores.
Triggers
Automatización en la base

Triggers: acciones automáticas ante eventos

Un trigger es un bloque de código que se ejecuta automáticamente cuando ocurre un evento sobre una tabla: INSERT, UPDATE o DELETE.

Puede ejecutarse BEFORE o AFTER del evento.

MomentoUso práctico
BEFORE INSERTValidar o completar datos antes de guardar.
AFTER INSERTRegistrar auditoría o actualizar acumulados.
BEFORE UPDATEEvitar cambios inválidos.
AFTER DELETEGuardar historial de registros eliminados.
Triggers
Ejemplo práctico

Ejemplo: auditar cambios de precio

En una cantina inteligente, los precios de productos pueden cambiar. Para análisis e IA, interesa conservar historial: cuándo cambió, de cuánto a cuánto, y quién lo cambió.

Esto permite analizar impacto en ventas, demanda y elasticidad de precio.

-- MySQL: guardar historial cuando cambia el precio CREATE TRIGGER trg_producto_precio_audit AFTER UPDATE ON producto FOR EACH ROW BEGIN IF OLD.precio <> NEW.precio THEN INSERT INTO producto_precio_historial (id_producto, precio_anterior, precio_nuevo, fecha_cambio) VALUES (OLD.id, OLD.precio, NEW.precio, NOW()); END IF; END;
