Bases de Datos + IA

Del dato guardado al dato inteligente

Evolución, organización, modelos de bases de datos y cómo se conectan con soluciones de Inteligencia Artificial.

Idea central

Una IA aprende, predice o recomienda mejor cuando los datos están bien almacenados, estructurados, protegidos y consultables.

¿Por qué hablamos de bases de datos?

Desde registros manuales en arcilla, papiros o libros, la humanidad buscó conservar información. Con las tarjetas perforadas y luego las computadoras, el almacenamiento pasó de ser físico y manual a ser digital, procesable y consultable.

Hoy, una base de datos no es solo “guardar datos”: también define cómo se organizan, cómo se validan y cómo se accede a ellos.

Relación con IA

La Inteligencia Artificial necesita datos históricos, limpios y disponibles. Por eso, una mala base de datos puede generar modelos de IA con errores, sesgos o resultados poco útiles.

Evolución de las BBDD

1ª generación · 1970-1980
Modelos jerárquicos y de red. Estructuras rígidas, navegación entre registros y mantenimiento complejo.
2ª generación · 1970-1990
Modelo relacional, SQL, integridad referencial, normalización y transacciones ACID.
3ª generación · 1990-actualidad
Bases orientadas a objetos y NoSQL para datos no estructurados, flexibilidad y escalabilidad.
4ª generación · 2010-actualidad
NewSQL y bases de datos en la nube: ACID + escalabilidad + alta disponibilidad gestionada.

Organización de una BBDD

Estructuras

Definen tipos, formatos, entidades, atributos, relaciones y métodos de acceso.

Reglas de integridad

Indican qué condiciones deben cumplir los datos para ser aceptados y registrados.

Operadores

Permiten consultar, insertar, modificar, eliminar y administrar datos y estructuras.

Para IA, estas tres partes impactan directamente en la calidad del dataset usado para entrenar o consultar modelos.

Modelos jerárquico y de red

Jerárquico

Organiza los datos como árboles: un nodo padre puede tener muchos hijos, pero la navegación ocurre en una dirección.

🌳

Ejemplo: Facultad → Carrera → Materia → Estudiante.

De red

Permite vínculos más complejos: un nodo hijo puede tener más de un padre y representar relaciones muchos a muchos.

🕸️

Ejemplo: Estudiante cursa varias materias y cada materia tiene muchos estudiantes.

Modelo relacional y SQL

El modelo relacional representa la información mediante tablas relacionadas entre sí.

Cada fila es un registro, cada columna es un atributo y las relaciones se implementan usando claves.

Idea clave: una tabla puede “apuntar” a otra usando una clave foránea.

Ejemplo real: cantina inteligente

Contexto

La cantina del campus registra clientes, fecha de nacimiento, preferencias de alimentos y bebidas, ventas realizadas, producto, cantidad, importe y medio de pago.

Uso con IA

Con datos históricos se puede construir un sistema de recomendación:

  1. Detecta productos favoritos por perfil.
  2. Predice demanda por hora o día.
  3. Recomienda combos personalizados.
  4. Reduce desperdicio ajustando stock.

Flujo: de BBDD a IA

1. Registrar

Datos de clientes, ventas y productos.

2. Limpiar

Evitar duplicados, nulos y errores.

3. Analizar

Buscar patrones y relaciones.

4. Predecir

Recomendar, clasificar o anticipar demanda.

Mensaje clave: no hay IA útil sin datos confiables, trazables y bien modelados.

Conclusión

Las bases de datos evolucionaron desde estructuras rígidas hasta plataformas relacionales, NoSQL, NewSQL y en la nube. Para IA, el objetivo no es solo almacenar: es disponer de datos correctos, consistentes y útiles para tomar mejores decisiones.
